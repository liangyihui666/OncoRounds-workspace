# 肿瘤医生大查房项目介绍稿

## 30 秒概括

我做的项目叫“肿瘤医生大查房”，英文名是 OncoRounds。它是一款面向年轻肿瘤医生的循证临床决策训练产品。我们把一个真实脱敏的纵向肿瘤病例，整理成病例摘要和完整病程轴，再按照诊疗时间顺序生成 5 道临床决策题。医生答题后不仅能看到答案，还能看到对应指南或临床研究证据，以及自己在治疗决策、分子诊断、疗效复评、耐药管理和不良反应管理等维度的表现。我的核心工作是完成产品方案、FastGPT 工作流、循证规则、安全校验和前端数据合同的设计。

## 5—8 分钟完整介绍稿

### 一、项目背景

我做的项目叫“肿瘤医生大查房”，英文名是 OncoRounds。

我最初关注到的一个问题是：年轻医生并不一定缺少指南或文献，但在真实病例里，仍然很难判断“这个时间点最应该做什么”。例如什么时候完善分子检测，什么时候调整系统治疗，治疗缓解后能不能考虑手术，出现严重免疫相关不良反应后应该如何处理。

这些问题并不是简单背诵知识点，而是要求医生结合患者当时已经获得的信息，按照诊疗顺序作出临床决策。因此，我希望把传统的病例阅读改造成一套可以反复训练、能够追溯证据的模拟查房产品。

### 二、产品如何使用

用户进入一个病例后，首先看到的是脱敏病例摘要和完整病程时间轴。系统不会一开始把所有答案都暴露出来，而是按照真实诊疗过程依次提问。

每个病例固定设置 5 道单项最佳选择题，每题 4 个选项且只有一个最佳答案。题目主要考查临床诊疗思路，而不是病例事实记忆。题目顺序一般从初始治疗决策开始，再到分子诊断、疗效复评、局部治疗或手术评估、耐药和后线管理，必要时加入严重不良反应处理。

完成答题以后，医生可以看到每题的正确答案、解析、关键学习点和对应证据，并在查房总结中看到不同能力维度的答题表现。

### 三、工作流的整体架构

整个系统的输入包括病例标题、疾病信息、初始病例资料、完整诊疗时间线、生物标志物、关键临床决策点、治疗相关不良反应和证据应用边界。

工作流收到这些信息以后，不会直接让大模型凭记忆出题，而是先进行五路独立证据检索：

第一路检索当前病种初始治疗和分子诊断的正式指南；

第二路检索疗效复评、手术评估、复发和后线疾病决策的正式指南；

第三路检索与病例实际治疗模式直接相关的临床研究；

第四和第五路分别检索第一、第二优先级严重治疗相关不良反应的正式指南。

拆成五路的原因是，不同类型的证据如果全部放在一个检索词里，很容易出现召回互相挤占。例如初始治疗资料会挤掉转化手术资料，糖尿病指南可能挤掉免疫相关肺炎指南。分路之后，每条检索链只服务一个明确的临床问题。

### 四、我重点解决的第一个问题：医学幻觉和证据错配

医疗出题最大的风险不是语言不流畅，而是题目看起来很专业，但答案实际上没有被当前证据支持。

为了解决这个问题，我设计了一套证据合同。每一道题只能绑定一条主要证据记录，并且必须精确保存 `doc_id` 和 `split_index`。证据对象还要包含证据类型、权威机构、来源标题、版本、章节、链接和证据摘要等 10 个字段。

生成模型不能把同一指南中不同分块的剂量、停药条件和再挑战条件拼在一起，也不能靠模型记忆补充指南年份、研究名称或推荐等级。当前片段支持到什么程度，题目就只能问到什么程度。

如果没有足够证据支持 5 道题，系统不会用病例事实题或普通文章强行补足，而是返回 `STOP_INSUFFICIENT`，并说明缺少哪些指南或临床研究。对我来说，能够安全地拒绝生成，也是医疗 AI 产品的一项核心能力。

### 五、我重点解决的第二个问题：纵向病例中的信息泄漏

真实病例往往跨越数月甚至数年。如果模型在设计初始治疗题时，使用了后来才出现的手术病理、耐药检测或患者结局，就会造成答案泄漏，也不符合医生当时的真实决策环境。

因此我规定，每道题只能使用题目时间点以及此前已经获得的信息。5 道题还必须按照整个诊疗流程排序，并尽量覆盖至少 3 个不同阶段。这样训练的不是医生对最终结局的记忆，而是他在每个时间点上的决策能力。

### 六、我重点解决的第三个问题：独立校验与发布门禁

题目生成完成后，不会直接给前端使用，而是进入独立校验节点。校验模型不负责重写题目，只负责检查病例事实、时间顺序、答案唯一性、证据定位、当前片段能否直接支持答案、题目是否重复以及来源字段是否真实。

校验结果分为三种：

- `PASS`：题目和证据均符合要求，可以发布；
- `REVISE`：有可以修正的问题，带着审核意见返回生成节点；
- `STOP_INSUFFICIENT`：证据本身不足，停止生成。

整个循环最多修订两次，避免工作流无限运行。最终只有 `PASS` 的 JSON 才能进入大查房 UI，这就是发布门禁。

### 七、严重不良反应的安全边界

在胃癌案例中，患者同时出现了 G4 免疫相关 1 型糖尿病并糖尿病酮症酸中毒，以及 G3 免疫相关间质性肺炎，所以我为严重不良反应设置了两个独立指南分支。

其中肺炎病例还存在支气管肺泡灌洗液病原学阳性、感染未排除的问题。为此我增加了明确规则：不能写“无感染证据”或“感染已经排除”，而要保留感染、定植、污染和免疫相关肺炎可能同时存在的边界，并考查病原学检查、并行处理和动态复评。这类规则体现了产品不仅关注答案正确，也关注医学表达的安全性。

### 八、前端和开发对接

为了让工作流结果可以稳定进入前端，我定义了统一的 JSON 数据合同，包括病例 ID、癌种、生成状态、难度、题目数量、题干、A 到 D 选项、答案、解析、学习点、能力维度和证据对象。

目前能力维度使用 6 个受控枚举：诊断与分期、分子诊断、治疗决策、疗效复评与局部治疗、耐药与后线管理、不良反应管理。前端根据每个维度的正确题数除以作答题数，生成查房总结。当前它属于教学反馈，而不是严格的心理测量或医生能力认证。

### 九、当前完成情况

目前已经完成并调试了 3 个具有代表性的肿瘤病例：

- HER2 阳性胃癌及两项严重免疫相关不良反应；
- 食管鳞癌转化治疗、根治手术和术后复发；
- ROS1 阳性肺腺癌的 CNS 进展、系统治疗、再次活检、耐药评估和临床研究边界。

这 3 个病例用于验证工作流能否处理不同癌种、不同诊疗阶段和不同证据组合，并完成了可供前端使用的 JSON 和 H5 演示数据。

此外，我还在规划 5.0 版本的病例资料预处理流程。目标是让用户直接上传 HTML 或其他文档，由系统先完成解析和结构化，区分患者事实、专家观点、宣传内容、参考文献和敏感信息，再经过人工确认后进入正式出题工作流。

### 十、项目价值与我的收获

这个项目最终形成的不是一次性的题目生成提示词，而是一套可以复用的生产链路：病例输入、证据检索、循证出题、独立校验、修订循环、发布门禁和前端展示。

我在项目中最大的收获是，医疗 AI 的可靠性不能只靠选择一个更强的模型，而要把医学边界设计成系统规则。包括证据分路、唯一证据定位、时间点约束、独立校验和证据不足时停止，这些机制共同决定了产品能否真正用于专业场景。

下一步我希望增加更多癌种和病例，并通过肿瘤医生盲审建立量化评估，例如证据匹配率、答案唯一性、临床阶段覆盖率、一次通过率和人工修订时间，再逐步验证实际教学效果。

## 面试官常见追问及回答

### 1. 为什么不用普通大模型直接出题？

普通大模型可以快速生成语言通顺的题目，但很难保证每个医学结论都有当前证据直接支持，也容易混用不同时间点的信息。我的方案把大模型限制在可追溯的证据范围内，并通过独立校验和发布门禁控制风险。

### 2. 为什么固定为 5 道题？

这是 MVP 阶段在病例覆盖度和医生使用负担之间的平衡。5 道题可以覆盖至少 3 个诊疗阶段，同时保持一次训练的完成成本可控。固定题数也便于前端展示、能力统计和不同病例横向比较。

### 3. 你如何降低幻觉？

主要有五层：限定正式证据类型、每题绑定唯一证据分块、禁止跨分块拼接、独立模型复核、证据不足时停止生成。JSON 门禁还会检查数量、选项、答案、证据字段和能力维度是否满足开发合同。

### 4. 项目中遇到的最大问题是什么？

最大问题不是生成模型，而是检索结果经常不够精准。最初把多个阶段放在同一个检索分支里，导致相同主题重复召回、关键阶段缺证据。后来我把指南拆成 A、B 两路，把严重不良反应再拆成两个独立分支，并根据病例实际阶段设置召回优先级，检索结果才更稳定。

### 5. 目前有没有量化结果？

目前完成的是 MVP 和 3 个代表性病例的流程验证，还没有足够的真实用户数据，所以我不会把未经验证的准确率或效率提升写进简历。现阶段可以量化的是系统结构，例如 5 路检索、5 道题、10 字段证据定位、最多两轮修订和 6 类能力维度。下一阶段会通过专家盲审和真实医生测试建立效果指标。

### 6. 你在项目里的核心贡献是什么？

我的核心贡献不是单纯编写提示词，而是把临床教学目标、循证规则、模型工作流和前端数据合同连接起来。我负责定义病例如何进入系统、证据如何分路、题目什么情况下可以成立、如何校验和停止，以及最终数据如何被 UI 稳定消费。

### 7. 如果继续做，你最先优化什么？

我会优先完成上游病例文件预处理和人工确认界面，同时建立标准化评测集。只有输入资料质量和评测标准稳定以后，再扩展更多癌种，才能避免病例数量增加后审核成本失控。

## 介绍时应避免的表达

- 不要说“完全杜绝医学幻觉”，建议说“通过证据定位、独立校验和停止机制降低风险”。
- 没有正式上线数据时，不要说“提升医生诊疗准确率 XX%”。
- 不要把能力维度百分比说成医生真实临床能力认证，它目前只是基于答题结果的教学反馈。
- 不要说系统替代医生决策，应表述为“医生教育和临床思维训练产品”。
