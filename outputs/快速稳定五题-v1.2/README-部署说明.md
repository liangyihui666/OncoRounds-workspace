## 本版关键变化

1. 保留指南A、指南B、临床研究初检、irAE A、irAE B五路主检索。
2. 仅当硬证据少于2条或机械题量容量少于5时才运行研究线索搜索；没有有效线索时不调用补检数据库。
3. 生成器只输出 `evidence_id`、`support_mode` 和 `evidence_summary`；其余证据字段由代码按唯一记录回填。ID在同一次归一化证据池及补检追加过程中稳定，不承诺在上游检索结果重排后跨运行永久不变。
4. 删除循环容器，展开为首轮生成/校验与一次条件触发的第二轮批量修订。
5. 成功固定5道进阶题，至少2道硬证据、至少2道病例临床推理，不固定具体题号。
6. 可解析的结构错误也继续接受独立医学校验；结构与医学错误合并后一次反馈。
7. 只有最终独立校验 `decision=PASS` 且 `score>=75` 才进入发布答复。
8. 六个医学检索节点的 `error` 与 `system_error_text`、知识库的 `system_error_text` 均汇入 `retrieval_health`；技术失败不得被解释为医学证据不足。
9. 校验输入保留当前内部候选，公开部分只传 `id + guidelineRef`映射；第二轮不再重复传递上一轮完整候选。
10. 临床研究必须能从未截断全文确认研究身份、设计、人群、干预、相关终点及本研究结果；结果只在 `Results/结果` 窗口内判定。protocol/design-only、未来入组/治疗、明确无本研究结果、把既往研究结果放进Results段、背景引用的他研结果和病例报告均不进入可用证据池。模型可见snippet仍不超过约1000字，并优先保留Results/结果与Conclusion/结论附近文本。
11. 研究线索提取同时读取FastGPT `datasetQuote` 的 `q/a/content/text/pageContent` 正文形态；`sourceName` 仅作来源标题，不会再遮蔽正文中的 `PROFILE 1014` 等研究线索。
12. 首轮/第二轮装配拒绝重复根JSON键；PATCH合并后还会逐题核对授权题解析值，阻断“原始切片与 `JSON.parse` 看到不同 `questions`”的歧义发布路径。

- `题目生成-首轮`、`题目修订-第二轮`：Qwen3.5-Plus，关闭思考，温度0.1，回复格式 `json_object`，回复上限8192，Vision关闭。
- `知识库搜索` 只在证据容量不足时进入；保留内置“问题优化”，模型使用系统默认、优化背景留空，用于从长病例决策中提取药物与治疗阶段关键词。
- `题目校验-首轮`、`题目校验-第二轮`：Qwen3.5-Plus，开启思考，推理强度medium，温度0.1，回复格式 `json_object`，回复上限16384。
- `irAE锚点轻量回退`：保持原配置。

## 导入与核验

按“一次核验一个可见动作”执行：

1. 在FastGPT中复制当前线上工作流，命名为v1.2测试副本。
2. 仅向测试副本导入本目录的可导入JSON。
3. 保存后先确认五路检索节点、两个生成/修订节点、两个校验节点和三个最终答复均存在，且没有循环节点。
4. 用同一脱敏ALK病例完整运行一次；首轮 `PASS` 时第二轮节点应不执行，首轮 `REVISE` 时第二轮必须收到 `repair_packet`。首轮可解析时同时传上一轮草稿；完全空或不可解析时允许按 `FULL` 从病例包重建。
5. 展开并保存：最终证据注册输出、两轮装配/硬检输出、两轮校验完整JSON、最终发布状态。
6. 连续运行三次后再进入20病例A/B验收；未达标时保留线上旧版本。

## 发布门禁

- `PASS && score>=75`：发布恰好5题。`score` 必须是JSON number且为0至100整数；字符串、小数或越界值都失败关闭，不四舍五入。
- `STOP_INSUFFICIENT`：发布0题并返回具体缺失证据。
- 第二轮仍为 `REVISE`、结构失败、JSON解析失败或执行异常：统一为 `REVISE_EXHAUSTED`，发布0题。
- 机械检查通过只是必要条件，不构成医学发布授权。
