| 环节 | 发现的问题 | 修改 |
|---|---|---|

| 指南检索 B | 接收了决策点变量但代码没有使用，仍偏向初始治疗 | 纳入复评、后线、局部协调及并发情况的决策点；保留实际方案、分子信息和完整源句，总长仍≤480字符 |
| 首轮生成、第二轮修订 | 规则累积、重复要求较多 | 两份提示词重写合并，分别从3436降到2923字符、4035降到3212字符；修订输入删去逐选项重复20次的同一句要求 |
| 题目质量 | 重复考点、空泛干扰项、适用范围被扩大 | 保留跨题近似选项定位、答案初始布局和唯一正确项检查要求；进一步明确癌种、治疗阶段、未知指标、疗效确认等边界；相似度只提示复核，不自动判医学对错 |
| 五题输出 | 缺口字段位于长输出末尾；Q5有缺字段时难定位 | 缺口字段前置，每题仍需完整13字段和四项理由；失败保留两轮原文及可解析的第二轮草稿，不拼凑缺题 |
| 单例→批量 | 子应用版本、具体失败状态和原文诊断在外层被丢弃 | 增加明确的批量传输模式，贯通版本、错误类型、引用正文及失败原文 |
| 批量最终检查 | 零题统一算未完成；末层仅检查解析非空 | 区分格式错误、执行错误、证据不足、题量不足；复核题号、四选项、答案及四行解析，保留原文件位置 |

首轮与修订仍使用 **Qwen3.8 Flash**，模型参数未变。成功仍必须完整 **5题**，最多2道明确标记的延伸情境，不调换已合格题的选项。清洗、提取和原有按需回退属于其他环节，不能把“两轮出题”理解为整个流程只有两次模型调用。

## 输出变化

普通单例输出仍为 `{Questions, detail}`。

新版批量最终回复为 `{output_data, batch_report}`：题目和病例页放在原来的 `output_data` 数组，诊断放在 `batch_report.items`，不会混进学员题干和解析。若外部程序原先直接接收批量根数组，需要改为读取 `output_data`。

批量通过固定输入 `__ONCOROUNDS_BATCH_V2__` 请求单例附带执行报告；普通单例不需要填写这个标记。旧版单例返回仍可被新版批量接收，但无法恢复旧结果已丢失的诊断。

| 报告状态/代码 | 含义 |
|---|---|
| OUTPUT_READY | 五题通过程序结构检查，未代表独立医学审核通过 |
| FORMAT_ERROR | 模型输出或题目字段未通过程序检查 |
| STOP_INSUFFICIENT | 上游声明证据不足，未形成题组 |
| INCOMPLETE_QUESTION_SET | 有草稿但没有完整五题 |
| UPSTREAM_ERROR / CHILD_WORKFLOW_ERROR | 上游返回或应用执行异常 |
| NO_COMPLETE_QUESTION_SET | 旧格式零题结果，未提供可验证的具体运行状态 |
