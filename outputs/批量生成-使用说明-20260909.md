# 批量生成：最多 10 个病例文件

导入文件：`批量生成-最多10文件-三连原样结果-20260909.json`。

基于用户提供的 `C:/Users/admin/Downloads/批量生成.json` 修改，原文件保留。保留原有 5 个节点的 ID，以及“三连”的应用 ID `6a991c7e2a5b103c1841ea95`。交付文件共 12 个节点、10 条连线。

## 使用

在 FastGPT 中导入这份完整工作流。在“病例文件（1–10个，每个文件一个病例）”上传框一次选择文件，输入“开始批量生成”并提交。每个文件应对应一个独立病例。支持的具体文件类型沿用三连现有文档解析能力。

每轮只向三连传入当前文件，按上传数组顺序依次运行。三连的历史对话设为 0，禁止中间串流；它的应用 ID 和内部出题、审核、证据、终选逻辑保持不变。批量应用不更新三连线上配置，也不内嵌或替换其工作流。

依赖：该应用 ID 实际调用的三连版本应已具备 `{Questions, detail}` 单一最终输出。仅在本地生成过统一输出文件，不代表该应用线上已使用它；如返回 `INVALID_RESULT`，应检查三连实际运行版本。

## 结果

最终回复只有一个可解析的 JSON 数组。数组第 1 项对应上传的第 1 个文件，依次类推。每个正常结果保持三连返回的 `{Questions, detail}` 对象，不另行改写题目、证据、状态或病例详情，也不生成额外审核结论。

这是一次批量回复中的多份 JSON 对象，不会自动创建多个下载附件。比如上传 3 个文件，全部正常时返回包含 3 个三连最终结果的数组；不是将 3 个病例合成一套题。

- `insufficient` 以及当前不足分支的 `detail: {}` 原样保留。
- 调用失败、空回复、非法 JSON 或契约不符：该位置返回 `error` 对象，包含从 1 开始的 `file_index`、错误代码和说明。原始诊断保留在内部运行详情中。可捕获的单文件失败后继续下一文件。
- 循环容器异常中断且错误分支能够继续执行时，保留已累计结果，剩余位置标记 `BATCH_INTERRUPTED`。用户停止、整次请求断开或平台强制超时不保证能执行最终汇总节点。
- 空列表、超过 10 个文件或包含无效文件项时，在调用三连前拒绝，不会静默截取前 10 个。

## 修改范围

1. 配置全局文件上传变量，最大文件数为 10，增加入口数量校验及每批结果初始化。
2. 将现有三连节点放入现有数组循环；当前元素是只含一个文件的数组，同时绑定子应用文件变量及本轮对话附件。
3. 分别连接正常与异常分支，累积每轮结果到循环外初始化节点的输出，避免新版循环只留下最后一轮结果。
4. 循环完成后序列化全部结果，通过唯一指定回复节点输出 JSON 数组。

循环与状态保存方式核对了 [FastGPT 官方循环文档](https://doc.fastgpt.io/zh-CN/guide/build/workflow/nodes/loop_run)、[官方循环执行源码](https://github.com/labring/FastGPT/blob/main/packages/service/core/workflow/dispatch/loopRun/runLoopRun.ts) 和 [子应用调用源码](https://github.com/labring/FastGPT/blob/main/packages/service/core/workflow/dispatch/child/runApp.ts)。原导出已使用新版 `loopRun` 节点；官方文档对应 4.15.0 及以上版本。
