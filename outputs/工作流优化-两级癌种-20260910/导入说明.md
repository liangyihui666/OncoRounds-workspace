# OncoRounds 三套工作流测试版

本包基于「题目生成 (6).json」「三连 (5).json」「批量生成 (2).json」修改，保留原导出文件和线上版本。只完成离线代码与契约校验，尚未在 FastGPT 导入或试跑。

## 按顺序导入，并重新绑定

1. 新建测试应用，导入 `01-题目生成-两级癌种-测试版.json`，保存为题目生成测试版。
2. 新建测试应用，导入 `02-三连-两级癌种-测试版.json`。将其中「题目生成」「题目生成 #2」「题目生成 #3」三个调用节点全部重新选择为上一步的新应用。
3. 新建测试应用，导入 `03-批量生成-两级癌种-测试版.json`。将并行容器中的「三连」调用重新选择为第二步的新应用。
4. 检查重绑后的变量：三个生成调用的 `cancer_type`、`second_cancer_type` 分别引用前方代码节点的同名输出；批量调用的 `case_source_file` 引用「循环开始 → 当前元素」，保持文件数组类型。三个生成调用各保留不同的教学侧重。

**必须先重绑，再试跑。导出文件中的旧应用 ID 仍保留占位，直接运行会调用旧应用。** 生成调用旧 ID 为 `6a96a10d67bd869e3352af48`，批量内三连旧 ID 为 `6a991c7e2a5b103c1841ea95`。未修改线上应用，也未替用户发布新版本。

## 本次变化

- `disease` 保留具体原发诊断供检索；结构化提取选择 CSV 二级名称，代码生成展示大类。脑部归头颈部、乳腺归胸部、已确认的男性生殖瘤种归泌尿系。CSV 共 132 个不同二级名称，22 个尚未确认一级归属的名称保留二级、一级留空；无法确定二级则两个字段均留空，并在内部记录原因。
- 最终仍为 `{Questions, detail}`，外层仅新增 `second_cancer_type` 分类字段：与 `cancer_type` 一同写入 `Questions` 和非空 `detail`，零题的空 `detail` 保持 `{}`。展示使用 `cancer_type`，推荐可使用 `second_cancer_type`。
- 目标每个病例 5 题，实际 1～4 题也输出；零题返回 `insufficient` 和原因。三组分别完整生成后择优，完全重复候选合并，不复制凑数。
- 保留真实医学审核、最多一次修订。最终采用第二轮有效题目，第二轮解析/合并失败或无有效题目时回退首轮，并记录回退原因。成功生成用 `OUTPUT_READY` 表示，医学判断仍记录在审核字段中；`publishable` 仅保留医学通过状态，不作为结果输出开关。
- 修复 A1 初始分期证据漏接，并去除 A1 入池过滤中残留的肺癌专用限制。审核读取绑定记录的原始正文；候选筛选使用压缩文本。无来源依据的引用字段不补造。
- 补检按需触发；明确无不良事件时不触发该路检索。统一生成、审核、修订规则，强调时间阶段、研究人群、评分体系及病例未知事实的边界。
- 终选只返回候选 ID；解析失败、无效 ID 或重复选择时按审核问题、考点重复情况和稳定顺序回退。清洗、提取、终选关闭不必要思考，终选为 JSON 输出、4096 输出 token；原模型和检索参数保留，独立医审保留思考配置。
- 批量接受 1～10 个文件，并发上限 10、自动重试 0。输出数组按上传顺序排列，单文件失败保留该位置的 `error` 对象，不丢其他结果。三组调用和关键生成/审核节点补接错误分支。

## 校验与试跑

详见同目录 `离线校验报告.md`。完成确定性代码、15 份已整理病例的分类映射及异常分支校验；没有调用模型重新提取或生成 15 份病例。

导入并重绑后，先用一个病例检查字段和引用，再用 6～10 个文件检查并发、失败位置及实际耗时。部署版本、模型限流、知识库返回内容和运行耗时需要平台试跑确认，不承诺未经实测的速度提升。

实现时核对了 FastGPT 官方的[并行节点说明](https://github.com/labring/FastGPT/blob/main/document/content/guide/build/workflow/nodes/parallel_run.en.mdx)及[执行引擎错误分支实现](https://github.com/labring/FastGPT/blob/main/packages/service/core/workflow/dispatch/index.ts)；本包保留原导出的节点类型和内部版本约定。
