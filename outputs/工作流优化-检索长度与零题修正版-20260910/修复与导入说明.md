# 检索长度与零题输出修正版

本次仅交付「题目生成」测试工作流。底稿为本地「参数传递修正版」，未操作线上应用。

## 已确认的问题

1. 用户提供的实际运行输入中，A1、A2、B和原始研究四路均返回 `Tool input validation failed: /query must NOT have more than 500 characters`。该限制也存在于本地检索工具参数的 `customJsonSchema.maxLength=500` 中。工具在检索前拒绝了请求；这不代表数据库没有相关证据。调整返回结果的 `maxTokens` 无法解决输入 query 的长度限制。
2. 首轮生成返回了合法的 `insufficient`、零题和具体失败原因。两轮装配的不足分支把完整证据池对象交给 `validatorEvidence.map(...)`，本地均复现 `TypeError: validatorEvidence.map is not a function`。该异常与运行记录停在候选题装配、父流程收到空回复的现象相符。线上装配的错误输出尚未直接取得。

## 修复范围

- 四个检索词拼接节点保留原名称、节点 ID、`system_text` 输出 ID及原有连线，改为确定性代码节点。只组合具体原发疾病、相应病例字段的完整子句及简短检索方向；不再把教学分工和长篇出题规则塞入检索词。每路输出不超过480个JavaScript字符串单位，严于工具500字符限制。
- 超出字段预算的完整子句会省略并记录在 `query_report.omitted_segments`，不截断否定句、药名或数值以形成残缺断言。若具体 disease 超过130字符，优先用已传入的二级原发癌种并记录原因。完整病例、精确 disease、原始证据正文仍供生成和医审使用。短检索词可能遗漏某些召回线索，需在试跑中核对实际召回结果。
- 临床研究补检也限制组合长度，防止追加研究线索后再次超长。原有补检条件和无研究线索时的空输出不变。
- 两轮装配分别处理证据数组及完整证据池对象；不足分支保留对象结构与失败原因，引用正文从原始记录回填。
- 未变更模型、思考配置、重排规则、数据库参数、工具绑定、癌种映射、全局变量和原有连线；三连与批量不另行改动。

## 导入测试

1. 将 `01-题目生成-检索长度与零题修正版.json` 导入为新的「题目生成」测试应用。
2. 在「三连」测试应用中，将三个题目生成调用都重新选择为这个新应用，确认病例变量与两级癌种仍正确绑定，并保存。调用节点的用户问题使用已有固定出题指令。
3. 先单独测试本次胃神经内分泌肿瘤病例。检查四路数据库节点不再出现500字符错误，并核对实际证据结果。若仍不足，应在最终结果看到具体不足原因，不能只得到空回复。

若需要直接合并到你当前已经调整过的导出版本，可用随附脚本针对当前「题目生成」导出打补丁；脚本保留未涉及节点与绑定。`repair_query_and_insufficient.py` 和 `compact-query.js` 必须放在同一文件夹中。命令：`python repair_query_and_insufficient.py 当前题目生成.json 新测试版.json`。代码结构不匹配会停止，需先核对当前文件，不能强制覆盖。
