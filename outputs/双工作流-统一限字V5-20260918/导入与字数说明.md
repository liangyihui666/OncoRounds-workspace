# 双工作流统一限字 V5

## 文件与导入

1. 导入 `题目生成-统一限字V5-测试版.json` 为新测试应用，底稿是用户上传的 `题目生成 (10).json`。
2. 导入 `最终出题-统一限字V5-测试版.json` 为新测试应用，底稿是基于用户“最终出题.json”持续修改的V4。
3. 打开新“最终出题”里的“题目生成”调用节点（eG3SWqAiKdmeb57I），**重新选择刚导入的V5题目生成应用**，核对病例变量绑定。导出文件保留旧应用ID，离线无法得知平台新建应用ID，不能自动完成这一步。
4. 开发接口或批量父应用切换到新的“最终出题”测试应用后试跑。已有病例JSON不会自动更新。旧工作流与Downloads原文件均保留。

## 最终正文上限

汉字、字母、数字、标点、空格均按Unicode字符计数。

| 内容 | 上限 |
|---|---:|
| 首页标题、详情大标题 | 14 |
| 首页简介 | 48 |
| 详情副标题 | 40 |
| 摘要患者背景、当前评估重点 | 各40 |
| 摘要诊断与检查、治疗经过 | 各50 |
| 病程标题、时间标签、正文 | 16 / 32 / 90 |
| 题干 | 100 |
| 每个选项、答案文本 | 40 |
| 解析 | 100 |
| 核心要点 | 35 |
| phase、timepoint | 16 / 40 |
| 题目生成的证据摘要 | 80 |
| 内部病例概要case_summary | 180 |
| 每条缺口说明、内部risk_message | 120 |

来源元数据是明确例外：原指南/研究的名称、章节、版本、权威机构、定位信息及链接保持原值，不能为了缩短文案截断或改写。内部原始证据和审计记录也不删减。分类标签、病例ID等结构性标识不按正文裁剪。

## 如何处理超长

子流程首轮生成、两轮硬检/医审及第二轮修订统一使用以上规则。保留原有最多一次修订，不新增模型调用或重试循环。选项压缩在子流程完成并同步答案，父流程仍不改选项或答案。

两个流程最终均按真实字数再次检查。超限且未被安全修订的题目暂不输出，原题和原因保存在运行记录；保留其余合规题，重新连续编号并同步计数。第二轮没有合规题时，可回退到首轮合规题。没有合规题时返回insufficient，父流程detail为空。**因此实际题数可能减少**，不会为了达标复制题目，也不会切掉医学前提来凑字数。

病程仍按事件显示，先按完整分句拆卡；仍超90字且无法安全拆分时，显示“本阶段记录较长，暂不展示；完整内容保留在运行记录。”。这属于明确提示，不是病例事实。不会把超长原句回退到页面。

医学审核仍报告真实PASS/REVISE。过滤或重编号后不把原整组审核错误绑定到新题组。字数合规不等于医学审核通过，也不保证所有屏幕宽度下都只有一两行。

这些测试未调用真实模型；44例回归用于验证“保留项引用不变、超长项明确记录”，不表示原220题全部符合新长度。尚未平台导入和线上试跑，未承诺耗时降幅。
