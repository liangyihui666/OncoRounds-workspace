# 答后参考答案与原病例对照

## 文件与使用

1. `01-五题出题子应用-完整工作流.json`：在原有出题子应用中导入，包含两轮提示词、两轮程序检查及最终输出同步修改。
2. `02-OCR清洗与五题生成-完整工作流.json`：在原有OCR文本外层应用中导入，包含候选检查与最终JSON映射同步修改。沿用此前OCR文本入口，不接收图片、不重新OCR。

先备份原工作流，再替换现有子应用与外层。外层的子应用绑定沿用原文件；如果导入为新应用，需要在外层“题目生成”节点选择新的子应用。只替换其中一份会造成旧契约缺字段或外层丢字段。无需重新跑历史批次。

保留现有五题目标、所有检索节点、知识库、研究补检、模型标识、节点连线和调用次数。本次未切换模型、未改在线应用、未改本地页面源码，未调用付费API。

## 新字段

最终位置：`Questions.questions[].after_answer`。子应用每题由14字段增至15字段；公开题目新增此对象。根级schema_version仍保持原接口值；新增对象使用自己的schema_version="1.0"。

```json
{
  "schema_version": "1.0",
  "actual_management": {"status": "not_reported", "field": "", "quote": ""},
  "actual_outcome": {"status": "not_reported", "field": "", "quote": ""},
  "comparison": {"status": "unknown", "explanation": "原文未记载对应实际处理，无法判断一致性。"},
  "difference_reason": {"status": "not_reported", "field": "", "quote": ""}
}
```

actual_management、actual_outcome、difference_reason的status只能为documented或not_reported。documented须提供病例事实字段及其连续原句；not_reported的field和quote为空。

comparison.status取consistent、different、not_comparable、unknown。参考答案与病例做法不同但原文未交代原因时，说明必须明确“原文未说明差异原因”。没有对应实际处理时不能判一致/不同；延伸假设题必须not_comparable。患者原句与指南/研究证据分开核对。

没有记录实际结局或原因，不强制停止出题；保留未知。已有case_source_text时以其为回溯依据；只有结构化字段时，只能检查输入字段里的原句，不能声称已核对原始文献。

## 给页面开发的接入要求（说明，未修改页面）

只在提交本题答案后显示，题干、选项、评分均不使用after_answer。

第一块标题“本题参考答案”：读取answer、answer_text、explain、keyPoint与guidelineRef。

第二块标题“原病例实际处理及结局”：实际处理和结局分别读取对应quote，status=not_reported显示“原文未记载”。quote须按纯文本渲染，不能作为HTML执行。

对照说明：显示comparison.explanation；different时另显示difference_reason.quote，未记载原因则显示“原文未说明差异原因”。旧数据没有after_answer时显示“该病例尚未提供答后对照资料”，不得自动从指南解析或整条时间轴补填。

需要同步页面类型定义、接口解析/字段白名单和答后组件，避免新增字段再次被丢弃。导入工作流仅提供数据，不会自动改变现有页面显示。

## 验证范围

10项离线检查通过，包括完整JSON与节点引用、两轮契约、五题子应用到外层的字段保留、假原句与未知/假设边界、原有答案/选项/证据错误拦截。示例文件仅为非医学程序测试，不能作为教学题发布。

程序检查只验证格式和原句存在，不证明引用表达的是已发生事件、选项的医学结论成立或比较判断正确。这些语义仍需医学审核。维持publishable=false、medical_review_status=not_performed；未进行线上模型生成验证。
