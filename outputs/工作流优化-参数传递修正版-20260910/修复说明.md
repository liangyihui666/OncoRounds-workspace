# 参数传递修正版

已确认交付包缺陷：代码节点新增参数缺少 `canEdit: true`，界面能够展示变量引用，但参数未进入 `system_addInputParam`，代码执行时收不到值。旧包的本地测试直接注入 main(inputs)，未覆盖平台取参这一层。

平台规则依据：[运行参数装配](https://github.com/labring/FastGPT/blob/main/packages/service/core/workflow/dispatch/utils/runtime.ts)中只有可编辑参数进入动态参数对象；[代码沙箱入口](https://github.com/labring/FastGPT/blob/main/packages/service/core/workflow/dispatch/tools/codeSandbox.ts)只将该对象传入代码。

本次补齐题目生成和三连中 25 个代码输入参数的标记及自定义输入配置，覆盖两级癌种、第二轮合并状态、检索异常和三组调用异常。批量生成文件内容不变。所有参数值和引用、代码、提示词、输出定义、连线、全局变量及应用 ID 均与上一交付包相同。

按平台取参规则执行旧包：原 32 项中 7 项失败，复现癌种变空和第二轮合并状态丢失。修复后 35 项全部通过，包括实际肝癌病例的参数传递、全节点代码输入注册及子调用错误信息传递。测试仍为本地适配模拟，未在用户部署上执行。

这解决的是已确认的参数入口缺陷，尚未证明 8 份空回复的底层原因已经解决。不良反应检索为空、evidence_notes 被清空尚未在本补丁中修改。

## 应用到当前测试版

本目录 JSON 基于上一交付包，保留的是原包应用 ID，不包含用户导入后重新绑定的 ID。**建议提供当前实际使用的「题目生成」「三连」两份导出，将同一补丁应用到当前版本，保留已绑定应用及当前设置。** 不需要重新运行病例以导出配置。

如果自行使用本目录的完整工作流导入副本，仍须先将三连的三个调用重新绑定到新题目生成测试版，再将批量调用绑定到新三连，才能试跑；导入本身不等于完成重绑。

`repair_parameters.py` 是仅修上述参数定义的本地脚本：输入当前导出和一个新的输出路径，保持节点引用及应用 ID。使用方式：

```text
python repair_parameters.py 当前导出.json 参数修复后.json
```

它不连接 FastGPT，不发布，不自动替换线上版本。
